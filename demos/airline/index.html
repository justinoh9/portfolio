    About this demo

    Same as the original

    • The schema is the project’s create_tables.sql, unchanged: nine tables with their keys and CHECK constraints.
    • Search, seat checks, purchases, ratings, and the staff pages use queries ported from the PHP.
    • Every query runs in a real SQL engine and shows up in the panel.

    Different from the original

    • The original is PHP and MySQL on a server. This version uses SQLite compiled to WebAssembly, so it runs without a backend.
    • There’s no login, just the role switch at the top, and it doesn’t collect payment details.
    • The airline, people, and flights are made up. Dates are generated from today’s date.

    What I’d fix in the original

    • Hash the passwords. The class project stores and compares them as plain text.
    • Switch from escaped strings to prepared statements, which this demo uses.
    • Put the seat check and ticket insert in one transaction so two people can’t buy the last seat. This demo does that too.
    • Only let people rate flights they actually took. The original doesn’t check, and here the interface handles it.
